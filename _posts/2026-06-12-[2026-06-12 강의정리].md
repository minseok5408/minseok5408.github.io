## 1. 문제와 접근

GraphRAG CLI를 사용할 때는 명령 실행 성공과 생성된 인덱스의 품질을 따로 확인한다. 설정을 바꾸어 인덱싱하고 산출물을 읽는 흐름을 통해 추출 결과와 검색 방식의 차이를 살펴본다. 실험마다 입력, 설정, 캐시 사용 여부를 분리해 비교 가능한 조건을 남긴다.

```text
graphrag init
  ↓
settings.yaml 수정
  ↓
input 문서 복사
  ↓
graphrag index
  ↓
parquet artifact 분석
  ↓
graphrag query local/global/drift
```

```python
def prepare_input(root: Path, source_files: list):
    input_dir = root / "input"
    input_dir.mkdir(exist_ok=True)

    copied = []
    total = 0
    for src in source_files:
        src = Path(src)
        dst = input_dir / src.name
        shutil.copy(src, dst)
        copied.append(src.name)
        total += dst.stat().st_size

    return {"copied": copied, "total_bytes": total}
```

## 6. gleaning 비교 실험

추가 추출 횟수를 비교할 때는 엔티티·관계 개수와 함께 실제로 새로 얻은 근거를 확인한다. 개수 증가만으로 품질 향상을 판단하지 않고, 중복이나 잘못된 관계도 늘었는지 살펴본다. 처리 시간은 캐시를 사용한 실행과 분리해서 비교한다.

`max_gleanings`는 한 chunk에서 추가 추출을 몇 번 더 시도할지 정한다.

```python
def setup_project_with_gleaning(suffix, n_gleanings):
    root = Path(f"ragtest_0612_g{suffix}")
    root.mkdir(exist_ok=True)

    if not (root / "settings.yaml").exists():
        os.system(f"graphrag init --root {root} --force")

    sp = root / "settings.yaml"
    s = yaml.safe_load(sp.read_text())
    s["models"]["default_chat_model"]["model"] = "gpt-4o-mini"
    s["models"]["default_embedding_model"]["model"] = "text-embedding-3-small"
    s.setdefault("extract_graph", {})["max_gleanings"] = n_gleanings
    sp.write_text(yaml.safe_dump(s, allow_unicode=True, sort_keys=False))

    (root / ".env").write_text((PROJECT_ROOT / ".env").read_text())
    (root / "input").mkdir(exist_ok=True)
    for txt in input_dir.glob("*.txt"):
        shutil.copy(txt, root / "input" / txt.name)

    return root
```

```python
def compare_gleaning(gleaning_runs):
```

## 9. NetworkX 변환과 시각화

parquet artifact를 NetworkX 그래프로 바꾼다.

```python
import networkx as nx


def to_networkx(arts) -> nx.DiGraph:
    G = nx.DiGraph()

    for _, row in arts["entities"].iterrows():
        G.add_node(
            row["title"],
            type=row.get("type", "unknown"),
            degree=int(row["degree"]),
            description=str(row.get("description")),
        )

    for _, row in arts["relationships"].iterrows():
        if row["source"] not in G:
            G.add_node(row["source"], type="unknown")
        if row["target"] not in G:
            G.add_node(row["target"], type="unknown")

        G.add_edge(
            row["source"],
            row["target"],
            description=str(row.get("description", "")),
            weight=float(row["weight"]),
        )

    return G
```

## 11. run_query 래퍼

Python 코드에서 CLI를 호출하고 stdout에서 답변을 추출한다.

```python
import subprocess


def run_query(method: str, question: str, root: Path = PROJECT_ROOT) -> str:
    result = subprocess.run(
        ["graphrag", "query", "--root", str(root), "--method", method, "--query", question],
        capture_output=True,
        text=True,
        timeout=300,
    )
    if result.returncode != 0:
        return f"ERROR: {result.stderr[:500]}"

    out = result.stdout
    for marker in [
        "SUCCESS: Local Search Response:",
        "SUCCESS: Global Search Response:",
        "Response:",
        "Answer:",
    ]:
        if marker in out:
            return out.split(marker, 1)[1].strip()
    return out.strip()
```

## 12. local/global 비교

이 절의 함수는 답변과 시간을 모으는 비교 도구다. 실행 결과를 남기기 전에는 어느 방식이 더 빠르거나 정확하다고 결론 내리지 않는다. 특정 엔티티 질문과 코퍼스 전체를 묻는 질문을 나누어 같은 기준으로 비교한다.

같은 질문을 local/global로 모두 실행해서 시간과 답변을 비교한다.

```python
def compare_methods(question: str) -> dict:
    out = {}
    for method in ("local", "global"):
        t0 = time.time()
        ans = run_query(method, question)
        out[method] = {
            "answer": ans,
            "elapsed_sec": round(time.time() - t0, 2),
        }
    return out
```

```python
q = "에빈 브로스와 콰빅스 연구소는 어떤 관계인가요?"
r = compare_methods(q)

for method, d in r.items():
    print(f"\n[{method.upper()}] ({d['elapsed_sec']}s)")
    print(d["answer"][:400])
```

## 15. 설정 변경의 효과를 산출물로 확인하기

설정 하나를 바꾼 실험마다 별도의 결과를 보관하면 어떤 관계와 요약이 달라졌는지 확인하기 쉽다. 입력 코퍼스와 모델 조건을 고정하고, 최종 답변이 달라진 질문에서 관련 산출물까지 거슬러 살펴본다.

CLI의 출력 형식과 산출물 컬럼을 사용하는 코드는 설치 버전과 함께 관리한다. 실행 시간을 비교할 때도 초기 인덱싱과 캐시 재사용을 구분해야 설정 변경에 필요한 비용을 해석할 수 있다.
