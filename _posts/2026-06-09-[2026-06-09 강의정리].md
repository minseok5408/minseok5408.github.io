## 1. 문제와 접근

여러 문서의 관계를 연결해야 하는 질문에서는 검색한 청크만으로 답변 근거가 완성되는지 먼저 확인해야 한다. 기본 RAG의 실패를 검색 누락과 관계 연결 부족으로 나누고, 그래프가 어떤 부분을 보완할 수 있는지 살펴본다. 그래프 도입 자체보다 필요한 근거 경로를 표현할 수 있는지가 판단 기준이다.

```text
Naive RAG:
  text -> chunk -> embedding -> top-k -> context -> answer

GraphRAG:
  text -> entity/relation -> graph -> community/path -> answer
```

```python
from pathlib import Path
from dotenv import load_dotenv

load_dotenv()

from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_community.vectorstores import FAISS
from langchain_core.messages import HumanMessage, SystemMessage
from langchain_text_splitters import RecursiveCharacterTextSplitter

llm = ChatOpenAI(model="gpt-4o-mini")
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
```

## 4. 임베딩과 cosine similarity

비슷한 문장끼리 임베딩 유사도가 높게 나온다.

```python
v1 = embeddings.embed_query("노라셋의 공명 하드웨어")
v2 = embeddings.embed_query(
    "노라셋 엔지니어링 그룹이 설계하고 제작하는 주력 제품은 공명 기반의 연산 하드웨어이다."
)
```

```python
import numpy as np


def cos(x, y):
    return float(x @ y / (np.linalg.norm(x) * np.linalg.norm(y)))


cos(np.array(v1), np.array(v2))
```

## 6. naive_rag 함수

검색된 top-k chunk만 컨텍스트로 넣어 답변한다.

```python
def retrieve(query, vs, k):
    return [d.page_content for d in vs.similarity_search(query, k=k)]
```

```python
def naive_rag(question, vs, k=3):
    chunks = retrieve(question, vs, k=k)
    ctx = "\n\n".join(f"[{i+1}] {c}" for i, c in enumerate(chunks))

    sys = SystemMessage(
        content="주어진 컨텍스트만으로 한국어로 답하세요. 컨텍스트에 답이 없으면 문서에서 찾을 수 없다고 답하세요"
    )
    user = HumanMessage(content=f"컨텍스트:\n{ctx}\n\n질문 : {question}")

    return llm.invoke([sys, user]).content
```

## 7. multi-hop 질문 실패 진단

답변 실패를 곧바로 벡터 검색의 한계로 결론 내리지 않는다. 연결에 필요한 청크가 검색됐는지 먼저 확인하고, 청크가 부족한 경우와 모두 있는데 관계를 조합하지 못한 경우를 나누어 본다.

다중 홉 질문은 한 번의 유사도 검색으로 필요한 모든 단서를 못 찾을 수 있다.

```text
질문:
  모리카이 센의 멘토가 쓴 논문은 무엇인가요?

필요한 추론:
  모리카이 센의 멘토 -> 탈라미르 헤쉬
  탈라미르 헤쉬가 쓴 논문 -> 공명 프레임
```

```python
def question_contains_answer(chunks, key):
    return any(key in c for c in chunks)
```

```python
def multihop_diagnosis(question, vs, key, k=5):
    chunks = retrieve(question, vs, k=k)
    answer = naive_rag(question, vs, k=k)
    return {
        "key_in_chunks": any(key in c for c in chunks),
        "key_in_answers": key in answer,
        "answer": answer,
    }
```

## 10. 그래프 탐색과 경로 찾기

그래프에서 경로를 찾았다는 사실과 그 경로가 질문의 답을 뒷받침한다는 판단은 다르다. 연결된 노드뿐 아니라 관계의 종류와 방향, 각 관계의 원문 근거를 함께 확인한다.

```python
list(G_demo.successors("모리카이 센"))
list(G_demo.predecessors("모리카이 센"))
```

```python
def neighbors_with_labels(G, node):
    out = []
    for v in G.successors(node):
        out.append({"direction": "out", "relation": G[node][v].get("relation", ""), "neighbor": v})
    for u in G.predecessors(node):
        out.append({"direction": "in", "relation": G[u][node].get("relation", ""), "neighbor": u})
    return out
```

```python
def multi_hop_paths(G, src, tgt, max_hops=3):
    results = []
    for path in nx.all_simple_paths(G, src, tgt, cutoff=max_hops):
        rels = [G[path[i]][path[i+1]].get("relation", "") for i in range(len(path)-1)]
        results.append({"path": path, "relations": rels})
    return results
```

## 12. 자주 나오는 실수/주의사항

### 실수 1: naive RAG로 multi-hop을 해결하려고 함

```text
top-k chunk에 필요한 단서가 모두 들어오지 않으면 답이 틀리거나 빠질 수 있다.
```

### 실수 2: edge 방향 무시

```python
G.successors(node)
G.predecessors(node)
```

> 방향 그래프에서는 들어오는 관계와 나가는 관계를 구분해야 한다.

### 실수 3: chunk 크기 고정

```text
chunk_size=300이 항상 정답은 아니다. 문서 구조와 질문 유형에 맞게 조정해야 한다.
```

### 실수 4: 그래프와 원문 연결 없음

```text
그래프 노드/엣지만 있으면 근거 문장으로 돌아가기 어렵다.
나중에는 source chunk id를 함께 저장해야 한다.
```

## 13. 그래프가 필요한 문제인지 먼저 확인하기

관계가 여러 단계 이어지는 질문을 기준으로 벡터 검색의 실패를 살펴본다. 검색 범위나 질의 분해로 해결할 수 있는지와 명시적 관계 구조가 필요한지를 비교하면 그래프 구축 비용을 들일 이유가 분명해진다.

수동 그래프 예제는 관계를 표현하고 탐색하는 기준을 확인하는 단계다. 실제 문서에 적용할 때는 잘못 추출한 관계와 누락된 관계가 탐색 결과를 어떻게 바꾸는지도 별도로 평가해야 한다.
